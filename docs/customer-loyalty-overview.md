# Карточка клиента: обзор и программы

Выбран вариант «Обзор и программы». Общие функции в loyalty.js формируют карточки акций с количеством оплаченных товаров, шкалой до подарка и отдельным статусом доступного подарка. Android адаптер размещает контакты слева, акции и историю справа. Шкала состоит из отдельных сегментов до 20 единиц; большие пороги показываются непрерывным доступным progress без создания тысяч элементов.

Редактор в карточке задаёт целевое количество товаров: кнопки −/+, точный числовой ввод, обязательная причина и сохранение. Достижение порога формирует целевое состояние один подарок / ноль прогресса. При доступном подарке разрешено отдельное снятие с причиной. Права и учётные данные берутся из действующей административной сессии; повторный пароль не запрашивается.

Backend принимает целевой и исходный баланс, версию участия и стабильный requestId. Изменение баланса после открытия редактора вызывает конфликт. Повтор после потерянного ответа не повторяет операцию. Корректировки требуют связи, не блокируя обычные офлайн-продажи. Подтверждённое сервером изменение обновляет профиль и историю; открытый несохранённый редактор не уничтожается при фоне начисления.

Локальные JS/JVM проверки не запускались; регрессии выполняются Actions. Требуется приёмка на планшете: несколько акций, доступный подарок, корректировка с причиной, повтор запроса, новый оплаченный чек во время редактирования, потеря связи, длинное имя, экранная клавиатура и закрытие администрирования.
