# Лояльность на кассе, 19.10.2026

Новая карточка клиента не означает согласия. Неотмеченная по умолчанию опция создания открывает отдельное оформление участия после сохранения карточки. У существующего неучаствующего клиента в карточке заказа и административной карточке есть кнопка оформления. Сотрудник открытой смены предоставляет актуальные документы, сверяет телефон и отдельно подтверждает факт добровольного личного согласия. Согласие сохраняется сервером; Telegram для этого сценария не нужен. Без сети подключение не подтверждается.

Backend: /api/device/loyalty/terms и POST /api/customers/:id/loyalty/consent, только активное устройство. Сервер сохраняет версию документов, серверное время, устройство, сообщённую планшетом личность сотрудника и идентификатор запроса. Личность сотрудника является атрибуцией доверенного устройства, не отдельной серверной аутентификацией сотрудника. Повтор запроса идемпотентен; устаревшее окно не возобновляет отозванное участие.

При смене клиента чужой статус участия сбрасывается. Быстрый расчёт без подарка ожидает загрузку участия; при недоступном сервере обычная продажа остаётся доступной. Только явно неизвестный снимок может разрешиться перед отправкой. Известная версия согласия не подменяется более новой. Сервер проверяет время покупки относительно согласия. Пропуск начисления сохраняется как consent_required и отображается сообщением, сетевая ошибка оставляет pending.

Регрессии написаны в product-stock.test.cjs; локально POS-тесты не запускались, проверяются GitHub Actions. На физическом устройстве требуется: создание с согласием/без, существующий клиент, две разные пиццы и количество 2 одной пиццы, быстрый расчёт, отключение сети/повтор, доступный подарок, возврат, отзыв и новое согласие. Старые пропущенные чеки не изменяются автоматически и требуют отдельного рассмотрения.
