# Переместить заказ в чек

Три точки → «Переместить заказ в чек» → выбор отложенного → подтверждение → объединённый чек открыт. Выбранный чек удаляется из отложенных, остальные сохраняются. Клиент, название, дата создания, способ получения, доставка и связь сайта берутся от выбранного чека. Общие комментарии объединяются. Скидки по лояльности загружаются заново для выбранного клиента, выбранные подарки текущего клиента не переносятся.

Строки сохраняются раздельно с исходными количеством, ценой, ручной ценой, скидкой, модификаторами и комментарием. Новый идентификатор каждой строки исключает коллизии; кухонные отметки переназначаются независимо для обоих чеков. Ничего автоматически не печатается, остатки не списываются.

parked и currentOrderSession записываются одной критической операцией до смены runtime. Подтверждение повторно проверяет оба снимка. При сбое/повторном нажатии нет дублирования или потери товаров. Частично оплаченный заказ не переносится. Текущий заказ с webOrderId должен завершаться отдельно: перенос с потерей внешней связи запрещён. В выбранный веб-чек можно переносить обычные текущие товары; его внешняя связь сохраняется.

Приёмка: варианты/скидки одинакового товара, перенос и дальнейшее откладывание/оплата, печать только непечатанных количеств, отказ storage и повтор, закрытие/устаревание выбора, восстановление текущей сессии, 1024×768/1280×800. Физический планшет/принтер проверяются отдельно.

Автоматическая кухонная печать при оплате использует объединённый printedItems и отправляет только положительную разницу. Legacy kitchenPrinted без массива сохраняет прежнее правило пропуска.
