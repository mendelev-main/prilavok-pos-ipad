## Рабочий процесс

Работа ведётся по цепочке:

1. Конституция задаёт постоянные правила проекта.
2. `ROADMAP.md` определяет приоритет следующего направления.
3. Для существенного изменения создаётся отдельный каталог `specs/NNN-short-name/`.
4. `spec.md` фиксирует требования и критерии приёмки, `plan.md` — технический подход,
   `tasks.md` — исполняемые шаги, `results.md` — фактические доказательства проверки.
5. После завершения каталог спецификации сохраняется как история развития системы.

`ROADMAP.md` не содержит подробных требований и чек-листов. Текущее устройство системы описывается
в `docs/ARCHITECTURE.md`, а новые или изменяемые требования — только в соответствующей спецификации.
Версия, дата и границы каждого результата проверки фиксируются рядом с результатом.
