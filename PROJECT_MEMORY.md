# PrilavokPOS Project Memory

Этот файл содержит постоянные правила проекта.

## Архитектура
- iPad POS приложение
- Swift + WebView интерфейс
- Backend: Railway
- Database: Supabase

## Основные правила разработки

1. Не менять существующий функционал без проверки зависимостей.
2. Каждая новая функция должна проверяться в четырех местах:
   - интерфейс;
   - логика данных;
   - сохранение;
   - отображение/печать.
3. Приоритет: стабильность кассы.
4. Все изменения должны учитывать iPad touch интерфейс.
5. Не менять дизайн основных экранов без согласования.

## UI правила
- Стиль: современный POS, ориентир Loyverse.
- Крупные элементы управления.
- Скругленные блоки.
- Минимум лишних действий.

## Ошибки разработки

### Общий принцип
Если исправляется ошибка отображения, проверить также бизнес-логику.

### Доставка
Проверять:
- изменение типа заказа;
- пересчет суммы;
- сохранение заказа;
- движение денег в смене.

## Процесс работы
Крупные изменения должны содержать:
- описание задачи;
- измененные файлы;
- возможные риски;
- способ проверки.
