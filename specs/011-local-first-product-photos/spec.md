# Feature Specification: local-first фотографии товаров

**Feature Branch**: `main`  
**Created**: 2026-10-02  
**Status**: Automated acceptance complete; device acceptance deferred  
**Roadmap**: R3 Local-first фото товара  
**Finding**: A003-F07

## User Scenario

При сохранении товара карточка и выбранное фото сначала остаются на iPad. Недоступный backend или
timeout не отменяет локальное сохранение. Pending-фото можно повторно отправить при следующем
сохранении карточки без повторного выбора изображения.

## Requirements

- **FR-001**: Сохранять сжатый JPEG в Application Support приложения сразу после выбора.
- **FR-002**: Сохранять карточку в исходном ключе `products` до любой сетевой операции.
- **FR-003**: Использовать только добавочные `localImageId` и `imageUploadPending`; старые записи
  и старые версии должны продолжать читать и сохранять остальные поля.
- **FR-004**: Не включать локальный URL или JPEG в payload онлайн-меню.
- **FR-005**: Ограничить upload десятью секундами и не перезаписывать более свежие поля товара.
- **FR-006**: Повторять pending upload только по явному сохранению карточки.
- **FR-007**: Удалять заменённый или явно удалённый локальный файл после локального commit.

## Success Criteria

- **SC-001**: Ошибка backend оставляет сохранённую карточку и pending local image.
- **SC-002**: Ошибка локальной записи не запускает upload и не меняет `state`.
- **SC-003**: Успешный upload обновляет только поля фото в актуальной карточке.
- **SC-004**: Pending-фото читается из native sandbox для повторной отправки.
- **SC-005**: Полный Node suite и Simulator build проходят.
