# Feature Specification: WEB and parked orders presentation

**Roadmap**: R12

**Baseline**: M POS 130.54

**Date**: 2026-10-02

## Goal

Стандартизировать статическое оформление списков WEB-событий, восстановления подтверждения и отложенных чеков без изменения сетевых, storage, печатных и кассовых операций.

## User scenarios

1. Сотрудник открывает список событий и выбирает новый заказ с сайта.
2. После локального сохранения WEB-заказа сотрудник при необходимости выбирает время для повторного подтверждения.
3. Сотрудник подписывает, просматривает, открывает или удаляет отложенный чек в прежнем сценарии.

## Requirements

1. `web-orders.js` и `parked-orders.js` не содержат inline style attributes.
2. Статическое оформление строк, пояснений, комментариев и действий задаётся именованными CSS-классами.
3. WEB acceptance journal, ACK/retry, проверки остатков и сетевые запросы не меняются.
4. Транзакции park/resume/delete, данные текущего заказа и печать кухни не меняются.
5. Полная автоматизированная матрица и simulator build проходят.

## Success criteria

- В обоих модулях остаётся 0 inline style attributes.
- WEB events и parked orders сохраняют прежнюю структуру и действия.
- Соответствующие модальные окна корректны в светлой и тёмной темах.

## Out of scope

- Изменение жизненного цикла WEB-заказов и статусов backend.
- Новые сетевые триггеры или уведомления.
- Изменение формата `webEvents`, `webOrderAcceptances`, `parked` или `currentOrderSession`.
- Изменение оплаты, складских списаний и печати.
