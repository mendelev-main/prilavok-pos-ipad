# Feature Specification: безопасный запуск при повреждённой форме storage

**Feature Branch**: `main`  
**Created**: 2026-10-01  
**Status**: Automated acceptance complete; manual acceptance deferred  
**Roadmap**: R1 Production acceptance 130.52  
**Finding**: A003-F04

## User Scenario

Если локальный ключ содержит синтаксически корректный JSON неправильного корневого типа или
некорректные строки массива, POS запускается в ограниченном состоянии и показывает storage warning.
Исходное значение остаётся в localStorage для восстановления и не заменяется пустым значением.

## Requirements

- **FR-001**: Валидировать массивы записей и объектные настройки перед присваиванием в `state`.
- **FR-002**: Не менять префикс, ключи или формат корректных данных.
- **FR-003**: Не записывать автоматически нормализованное значение поверх повреждённого ключа.
- **FR-004**: Сохранить прежнее автоматическое добавление совместимых полей для корректного каталога.
- **FR-005**: Помечать storage broken, но завершать `loadAll()` и первый render.
- **FR-006**: Не добавлять сеть, миграцию или очистку.

## Success Criteria

- **SC-001**: `{}` вместо products и другие неверные корневые типы не выбрасывают исключение.
- **SC-002**: Исходная строка каждого повреждённого ключа остаётся байт-в-байт прежней.
- **SC-003**: Некорректная строка products отфильтрована только в памяти.
- **SC-004**: Полный Node suite и Simulator build проходят.
