# Feature Specification: Telegram-отчёт владельца из активного POS

## Цель

Владелец, Telegram ID которого вручную сохранён в сетевых настройках POS, получает в существующем боте кнопку «Получить информацию». По нажатию открытый POS формирует из локальных чеков текущей смены снимок: выручка, наличные, карта, количество чеков, продажи по категориям и позициям.

## Требования

- ID владельца сохраняется в существующую локальную запись `prilavok_telegram` до сетевого запроса.
- Backend хранит ID владельца в строке соответствующего активного устройства.
- Telegram ID берётся только из проверенного контекста бота и должен совпасть с ID, сохранённым POS.
- Продажи и чеки не переносятся в облачную БД; снимок существует только в памяти на время запроса.
- Backend отправляет запрос через уже открытый SSE-канал заказов. Новый heartbeat или периодическая синхронизация не добавляются.
- POS рассчитывает отчёт только из локальных данных открытой смены.
- Ответ POS принимается только с ключом того же устройства и одноразовым request ID.
- Если SSE-соединения нет или POS не ответил за восемь секунд, бот сообщает «POS не активен».
- Закрытая смена при активном POS возвращает «POS онлайн. Открытой смены сейчас нет».
- Ошибка отчёта не влияет на продажи, оплату, чеки, смены и локальное хранение.
