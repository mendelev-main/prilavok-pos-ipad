# Feature Specification: сотрудники и локальные права

**Feature Branch**: `main`

**Created**: 2026-10-02

**Status**: Implemented

**Input**: Продолжить production-аудит и постепенную модульную миграцию: проверить CRUD сотрудников и права администратора, устранить подтверждённую потерю изменений при storage failure и выделить домен из `pos.html` без изменения UI или данных.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Сотрудник сохраняется устойчиво (Priority: P1)

Создание и изменение сотрудника публикуются в памяти и UI только после успешной локальной записи.

### User Story 2 - Сбой хранения не меняет права (Priority: P1)

При ошибке storage исходный список, роль и дополнительные поля остаются без изменений, окно сохраняется для повтора и успех не показывается.

### User Story 3 - Ограничения доступа сохраняются (Priority: P1)

Выдача и снятие роли администратора требуют прежний пароль; активный сотрудник и администратор не удаляются; история чеков и смен не меняется.

### User Story 4 - Модуль сохраняет прежний runtime-контракт (Priority: P1)

Настройки, верхняя панель и смены используют те же глобальные функции после их переноса в отдельный classic script.

## Requirements *(mandatory)*

- **FR-001**: Сохранение MUST строить отдельный снимок сотрудников и записывать `prilavok_employees` до изменения `state.employees`.
- **FR-002**: Storage failure MUST сохранять исходное состояние, не закрывать окно и позволять повтор.
- **FR-003**: Повторное нажатие во время записи MUST NOT создавать дубликат.
- **FR-004**: Редактирование MUST сохранять неизвестные дополнительные поля существующей записи.
- **FR-005**: Формат массива и полей сотрудника, storage key, роли, пароль и UI MUST остаться совместимыми.
- **FR-006**: Модуль MUST загружаться после `shifts.js` и до startup.
- **FR-007**: Не добавлять сеть, миграцию, автоматическую синхронизацию, версию или изменение `project.pbxproj`.

## Success Criteria *(mandatory)*

- **SC-001**: Node regression и syntax checks проходят полностью.
- **SC-002**: Create/edit failure tests подтверждают отсутствие изменения памяти и ложного успеха.
- **SC-003**: Role/password, delete protection и repeated-save tests проходят.
- **SC-004**: Simulator build успешен, bundle содержит идентичный `employees.js`.
- **SC-005**: `pos.html` больше не определяет `saveEmployee` и уменьшается после extraction.
