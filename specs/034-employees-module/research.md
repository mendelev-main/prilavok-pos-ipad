# Research: сотрудники и локальные права

До изменения `saveEmployee` мутировал объект внутри `state.employees` или добавлял новую запись, затем вызывал совместимый `saveKey`, который сообщает ошибку отдельно и не откатывает память. UI всегда закрывал окно и показывал успех. При storage failure роль или сотрудник существовали только до перезапуска.

Удаление уже использовало безопасный порядок: новый массив записывался прямым вызовом adapter, затем публиковался в state. Поэтому тот же подход выбран для create/edit. Critical journal для одного ключа не нужен.

Редактирование выполняется над полным клоном существующего массива: известные `name`, `phone`, `role` обновляются, а дополнительные legacy-поля сохраняются. Текущий пароль и ограничения удаления оставлены без изменений по явному решению владельца продукта.
