# Feature Specification: модуль каталога товаров

**Feature Branch**: `main`

**Created**: 2026-10-02

**Status**: Automated acceptance complete; device verification deferred

**Input**: User description: "Продолжить постепенную production-ready миграцию; следующим этапом вынести управление каталогом товаров без изменения данных и поведения."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Импорт дополняет каталог без потери данных (Priority: P1)

Администратор выбирает CSV, проверяет предварительный список и добавляет новые товары. Существующие
товары не заменяются, а новый runtime-state публикуется только после успешной локальной записи.

**Why this priority**: Ошибка импорта может повредить главный справочник POS.

**Independent Test**: Импортировать корректный и некорректный CSV, повтор, изменившийся preview и
ошибку storage, проверив прежний ключ и отсутствие частичных изменений.

**Acceptance Scenarios**:

1. **Given** корректный CSV, **When** импорт подтверждён, **Then** новые товары сначала сохраняются локально и затем появляются в state.
2. **Given** совпадающее имя, **When** строится план импорта, **Then** существующий товар не перезаписывается.
3. **Given** ошибка storage, **When** импорт подтверждён, **Then** каталог в памяти остаётся прежним.

---

### User Story 2 - Каталог легко искать и сортировать (Priority: P2)

Сотрудник ищет товар по названию или категории и сортирует таблицу по существующим колонкам.

**Why this priority**: Каталог должен оставаться удобным при большом количестве товаров.

**Independent Test**: Проверить Unicode-поиск, live filtering и все направления сортировки без
изменения порядка persisted-массива.

**Acceptance Scenarios**:

1. **Given** товары разных категорий, **When** введён текст, **Then** совпадения находятся по названию и категории.
2. **Given** выбран заголовок таблицы, **When** он нажат повторно, **Then** направление сортировки меняется.
3. **Given** сортировка и поиск, **When** они применены, **Then** исходный массив товаров и storage не меняются.

---

### User Story 3 - Каталог изолирован от монолита (Priority: P3)

Разработчик сопровождает импорт и таблицу товаров в отдельном production-компоненте, не затрагивая
карточку, рецептуры, категории, рабочую зону и кассу.

**Why this priority**: Узкая граница снижает риск для критичных товарных операций.

**Independent Test**: Компонент исполняется общей fixture, загружается до `loadAll()` и является
единственной реализацией функций каталога.

**Acceptance Scenarios**:

1. **Given** запуск POS, **When** выполняется первый render, **Then** catalog API уже доступен.
2. **Given** завершённый этап, **When** проверяется `pos.html`, **Then** в нём отсутствует дубликат реализации.

### Edge Cases

- BOM, запятые, точки с запятой, multiline и escaped quotes в CSV.
- Пустая, изменяемая, дробная или некорректная цена.
- Unicode combining characters и `ё` в поиске и категориях.
- Повтор товара внутри CSV и совпадение с существующим каталогом.
- Изменение каталога между preview и подтверждением.
- Двойное нажатие подтверждения.
- Ошибка localStorage.
- Товар без учёта остатка или с составной себестоимостью при сортировке.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: CSV parser и ограничения файла MUST сохранить текущее поведение.
- **FR-002**: Нормализация имён, совпадение существующих категорий и обработка дублей MUST остаться неизменными.
- **FR-003**: Импорт MUST оставаться additive и не перезаписывать существующие товары.
- **FR-004**: Новый каталог MUST сохраняться до изменения `state.products`.
- **FR-005**: Используется прежний ключ `products`, prefix и JSON-формат без миграции.
- **FR-006**: Поиск MUST учитывать только имя и категорию и сохранять Unicode-нормализацию.
- **FR-007**: Сортировка MUST оставаться presentation-only и не менять persisted order.
- **FR-008**: UI, тексты, кнопки, колонки и inline actions MUST остаться неизменными.
- **FR-009**: Этап MUST NOT переносить категории, product editor, recipes, deletion, workspace или checkout.
- **FR-010**: Сеть, версия и `project.pbxproj` MUST остаться неизменными.
- **FR-011**: Автоматизированные проверки MUST исполнять фактический production-компонент.

### Key Entities

- **CSV row**: исходное имя, категория и необязательная цена.
- **Import plan**: массив добавляемых и список пропущенных имён.
- **Imported product**: существующий совместимый объект простого товара с прежними defaults.
- **Catalog query**: нормализованная строка поиска.
- **Sort state**: ключ колонки и направление, хранящиеся только в runtime.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все 12 существующих catalog scenarios, новый boundary test и полный suite проходят.
- **SC-002**: Ошибка storage не меняет каталог в 100% соответствующих тестов.
- **SC-003**: Поиск и сортировка не создают storage writes.
- **SC-004**: В `pos.html` не остаётся реализации функций каталога.
- **SC-005**: Сборка включает компонент без изменения версии или Xcode-проекта.

## Assumptions

- Текущая структура товара и defaults импорта сохраняются без продуктовых изменений.
- Общие product, unit, cost, modal, render, storage и escaping helpers остаются runtime-зависимостями.
- Физическая проверка CSV picker и таблицы выполняется в общем финальном прогоне.
