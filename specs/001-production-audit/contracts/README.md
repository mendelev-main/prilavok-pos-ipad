# Проверяемые контракты

1. Storage: get(key,fallback,onError), set(key,value); JSON и prilavok_ неизменны.
   Ошибки записи должны быть доступны критической операции; текущий saveKey их поглощает (F01).
2. POS → backend: каталог вручную; availability/operational и web ACK — отдельные согласованные каналы.
3. WEB accept: POST /api/orders/:id/accept с readyEstimate, device key; local-first журнал.
   Значения: presets или at:HH:mm. Старые записи без estimate требуют совместимого recovery (F09).
4. Лояльность: /api/loyalty/sales и /reversal; идентификатор чека обеспечивает повторяемость,
   но не заменяет локальный durable pending (F02) и атомарность нескольких программ.
5. Checkout: подтверждённый телефон → клиент → заказ → позиции → tracking; частичная запись недопустима (F06).
6. Native bridge: LAN-печать не отменяет оплату; подтверждение TCP-отправки не доказывает печать на бумаге.
7. PDF/XLSX: выбранные метрики и период одинаковы в UI/экспорте; имя заведения в шапке;
   никакой записи/мутации исходных складских данных при экспорте.
