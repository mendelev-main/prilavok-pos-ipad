# Модель данных для проверки (без миграций)

| Сущность | Хранилище/граница | Инвариант проверки |
|---|---|---|
| Товар/рецептура | prilavok_products | Остаток и себестоимость согласованы с операциями; существующие ID сохранены |
| Чек/платежи/снимок списания | prilavok_orders | Один факт оплаты → один чек; возврат использует снимок, не новую рецептуру |
| Смена/кассовые движения | prilavok_shifts | Платежи и возвраты согласованы с кассой |
| Текущий/отложенный заказ | currentOrderSession / parked | Перезапуск не теряет заказ и не создаёт повторную продажу |
| Приёмка/заказ поставщику | receivings / purchaseOrders | Факт количества и средневзвешенная стоимость отражены однократно |
| Web acceptance journal | webOrderAcceptances | Локальная копия сохранена перед ACK; повтор не создаёт дубль |
| Лояльность чека | orders.loyaltySync / loyaltyReversal | Pending существует до отправки; retry/reversal не удваивает результат |
| Клиент/программа/ledger | backend customers / loyalty_* | Подтверждённый клиент привязан; подарок не начисляет следующий подарок |
| Checkout/verification | backend checkout_sessions / phone_verifications / orders / order_items | Одно подтверждение приводит к одному полному заказу или безопасному повтору |
| Outbox/ревизия | operationalOutbox / operationalRevision | Сохраняется до сети; старый ответ не заменяет новое состояние |

Все имена локальных ключей в таблице без префикса читаются через существующий prilavok_ adapter.
Таблица — область аудита, не предложение новой структуры БД.
