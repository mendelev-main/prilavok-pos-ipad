# Физическая проверка M POS 130.52 на iPad

Выполнять на копии данных или после проверенного backup. Для каждого шага записать версию iPadOS,
результат, фактическое сообщение, время и приложить фото/видео при ошибке.

## 1. Запуск и lifecycle

- [ ] Холодный запуск без интернета: рабочая зона появляется, текущие товары/смена/чек доступны.
- [ ] 20 циклов background → foreground: нет белого экрана, второго окна, двойного события или роста
  памяти ступенями.
- [ ] Принудительное завершение с непустым текущим заказом: после запуска восстановлены позиции,
  количества, комментарии, клиент, тип заказа и тариф доставки.
- [ ] iPad заполнен почти до лимита: POS показывает ошибку записи и не сообщает об успехе операции.
- [ ] Обновление поверх 130.52: товары, чеки, смены, папки, настройки и история сохранены.

## 2. Продажа и чек — P0

- [ ] Наличные, карта и split: ровно один чек, правильная оплата, одно списание рецептуры.
- [ ] Двойное быстрое нажатие оплаты не создаёт второй чек.
- [ ] Составной товар с вложенной рецептурой списывает каждое сырьё один раз и в нужной единице.
- [ ] Нехватка общего ингредиента блокирует оплату до терминального шага и не меняет остатки.
- [ ] Kill приложения на каждом шаге оплаты: после запуска journal завершается ровно один раз.
- [ ] Полный возврат восстанавливает снимок проданной рецептуры и кассу; повторный возврат запрещён.
- [ ] Старый чек без stock snapshot возвращается по legacy-правилам без выдуманного состава.
- [ ] Доставка не оплачивается без выбранного тарифа, включая тариф 0 Br.

## 3. Текущий и отложенный заказ — P0

- [ ] Отложить чек, перезапустить, продолжить: все поля и позиции совпадают.
- [ ] Возобновить отложенный чек и сразу завершить приложение: чек остаётся ровно в одном месте.
- [ ] Смоделировать отказ записи/нехватку места: текущий чек не очищается и успех не показывается.
- [ ] WEB-заказ принять, убить приложение до ACK и после ACK: один parked-заказ, без дубля.
- [ ] Legacy WEB-заказ без времени готовности предлагает восстановимый путь, а не вечный retry.

## 4. Смена и касса — P0

- [ ] Открытие смены, внесение, изъятие и закрытие переживают перезапуск.
- [ ] При ошибке локальной записи Telegram/печать не сообщают, что смена закрыта.
- [ ] Отрицательное, пустое, `Infinity`, очень большое число и десятичная запятая корректно
  отклоняются/нормализуются.
- [ ] Фактическая сумма, ожидаемая сумма и расхождение совпадают в UI, локальной истории,
  Telegram и печатном отчёте.

## 5. Склад, товары и документы — P0/P1

- [ ] Завершить инвентаризацию и перезапустить: остатки, история, дата и отсутствие черновика
  согласованы.
- [ ] Kill/ошибка записи во время завершения: либо всё старое, либо всё новое; черновик не теряется.
- [ ] Приёмка с частичной поставкой меняет остаток и средневзвешенную стоимость один раз.
- [ ] Kill во время приёмки: journal восстанавливает товары, заказ и документ прихода вместе.
- [ ] Создание/удаление заказа поставщику не оставляет частичный документ или дубликат истории.
- [ ] Редактирование товара офлайн сохраняет текстовые данные; фото получает явный статус ожидания.
- [ ] Циклическая/битая рецептура не сохраняется и не меняет прежний товар.
- [ ] Импорт CSV не создаёт категории и не перезаписывает существующие товары.

## 6. Сеть, WEB и лояльность

- [ ] Отключить интернет на каждом экране: локальная продажа, чек, смена и товары продолжают работать.
- [ ] Полуоткрытое соединение при проверке подарка: быстрый timeout и доступна продажа без подарка.
- [ ] После восстановления сети pending начисление/возврат лояльности отправляется ровно один раз.
- [ ] Публикация остатков начинается не раньше 10 минут, не отправляет каталог/цены и не меняет POS.
- [ ] Полная синхронизация запускается только вручную из сетевых настроек.
- [ ] Потеря SSE и возврат сети не создают дубль события/заказа.

## 7. LAN-принтер и native bridge

- [ ] Доступный принтер: чек, кухня и отчёт смены печатаются нужное число копий.
- [ ] Недоступный IP, отключённый Wi‑Fi и принтер в `.waiting`: операция завершается понятной ошибкой
  за ограниченное время; следующая печать работает.
- [ ] 20 параллельных заданий под Thread Sanitizer: нет data race/crash, по одному terminal event.
- [ ] Фото: отмена picker, запрет Photos, большой файл, background во время выбора — UI не зависает.
- [ ] Instruments после повторного открытия/закрытия сцены: `POSViewController` и WebView освобождаются.

## 8. Backup и отчёты

- [ ] Экспорт → чистая тестовая установка → импорт: совпадают товары, чеки, смены, склад, папки,
  незавершённый заказ и настройки.
- [ ] Повреждённый/неполный backup не изменяет текущие данные.
- [ ] PDF/XLSX за день, месяц и большой период открываются; суммы и строки сверены с чеками/приёмками.
- [ ] Многостраничный PDF: шапка только на первой странице, период виден на следующих.
- [ ] Настройки LAN-принтеров проверены отдельно: текущий backup 130.52 их не переносит.
