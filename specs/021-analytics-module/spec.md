## User Scenarios & Testing *(mandatory)*

### User Story 1 - Локальная аналитика сохраняет точные итоги (Priority: P1)

Сотрудник выбирает период и видит продажи, способы оплаты, себестоимость, прибыль, сотрудников,
категории и товары, рассчитанные по локальным чекам POS.

**Why this priority**: Неверные суммы аналитики могут привести к ошибочным управленческим решениям.

**Independent Test**: Задать период с оплаченным, возвращённым и находящимся за пределами периода
чеками и проверить все итоговые показатели.

**Acceptance Scenarios**:

1. **Given** чеки разных дат, **When** выбран период, **Then** учитываются только чеки внутри его границ.
2. **Given** возвращённый чек, **When** строится аналитика, **Then** он не входит в показатели продаж.
3. **Given** смешанная оплата, **When** строится аналитика, **Then** наличные и карта учитываются раздельно.

---

### User Story 2 - Аналитика остаётся доступной без backend (Priority: P2)

Администратор открывает аналитику без сети и продолжает видеть локальные показатели; недоступность
центральной лояльности отображается как отдельная ошибка.

**Why this priority**: Offline-first POS не должен терять локальную отчётность из-за backend.

**Independent Test**: Отклонить запрос показателей лояльности и проверить сохранность локальных расчётов.

**Acceptance Scenarios**:

1. **Given** backend недоступен, **When** запрашиваются показатели лояльности, **Then** локальная аналитика продолжает рассчитываться.
2. **Given** обычный сотрудник, **When** открыт экран, **Then** действующие ограничения видимости сумм сохраняются.

---

### User Story 3 - Домен изолирован от монолита (Priority: P3)

Разработчик сопровождает аналитику в отдельном production-компоненте без изменения кассы,
складского отчёта и данных.

**Why this priority**: Меньший `pos.html` снижает риск следующих изменений.

**Independent Test**: Компонент исполняется тестами, подключён до `loadAll()` и является единственной
реализацией функций аналитики.

**Acceptance Scenarios**:

1. **Given** запуск POS, **When** начинается первый render, **Then** API аналитики уже доступен.
2. **Given** завершённый этап, **When** проверяется `pos.html`, **Then** в нём нет дубликата функций домена.

### Edge Cases

- Пустой период без чеков.
- Граничные моменты начала и конца выбранной даты.
- Legacy-чек с одним полем `method` вместо массива `payments`.
- Возвращённый чек внутри периода.
- Удалённый товар или категория, сохранённые только в строке чека.
- Нулевая сумма способов оплаты.
- Backend лояльности недоступен.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Фильтрация чеков по периоду MUST остаться неизменной.
- **FR-002**: Расчёт выручки, оплат, себестоимости, прибыли и среднего чека MUST остаться неизменным.
- **FR-003**: Группировка по сотрудникам, категориям и товарам MUST сохранить legacy fallbacks.
- **FR-004**: Возвращённые чеки MUST исключаться из локальных показателей.
- **FR-005**: Ограничения видимости показателей для администратора и сотрудника MUST сохраниться.
- **FR-006**: Ошибка loyalty backend MUST NOT блокировать локальную аналитику или другие функции POS.
- **FR-007**: UI, тексты, периоды и inline actions MUST остаться неизменными.
- **FR-008**: Этап MUST выделить только домен аналитики.
- **FR-009**: Storage keys, JSON-форматы, версия и `project.pbxproj` MUST остаться неизменными.
- **FR-010**: Автоматизированные проверки MUST исполнять фактический production-компонент.

### Key Entities

- **Период аналитики**: локальные даты начала и окончания включительно.
- **Чек**: timestamp, total, payments/method, shiftId, items и returnedAt.
- **Показатели продаж**: revenue, cash, card, cost, profit и average check.
- **Группировка**: сотрудник, категория или товар с суммой/количеством.
- **Показатели лояльности**: необязательный server response, не являющийся источником локальных продаж.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все новые проверки аналитики и полный regression suite проходят.
- **SC-002**: Оплаченные, возвращённые и внешние по периоду чеки дают ожидаемые итоги во всех test scenarios.
- **SC-003**: Ошибка backend не меняет локальные чеки и рассчитанные показатели.
- **SC-004**: В `pos.html` не остаётся реализации функций домена.
- **SC-005**: Сборка включает компонент без изменения версии или Xcode-проекта.

## Assumptions

- Текущие формулы и ограничения доступа сохраняются без продуктовых изменений.
- `localDateString`, state, storage-free helpers, modal/render и loyalty transport остаются runtime-зависимостями.
- Физическая проверка экрана выполняется в общем финальном прогоне.
