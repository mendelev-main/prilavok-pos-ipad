# Feature Specification: атомарные заказы поставщикам

**Feature Branch**: `main`  
**Created**: 2026-10-01  
**Status**: Automated acceptance complete; manual acceptance deferred  
**Roadmap**: R1 Production acceptance 130.52  
**Finding**: A003-F11

## User Scenario

Создание заказа поставщику одновременно сохраняет параметры закупки товара и сам заказ. Удаление
ожидаемой приёмки одновременно сохраняет удалённый статус и аудиторскую строку истории. Сбой записи
не меняет экран, а прерванная запись восстанавливается целиком при следующем запуске.

## Requirements

- **FR-001**: Создавать неизменяемые снимки товаров и заказов до записи.
- **FR-002**: Сохранять создание заказа одним critical journal.
- **FR-003**: Сохранять удалённый заказ и запись истории одним critical journal.
- **FR-004**: Менять `state` и очищать форму только после успешного commit.
- **FR-005**: Блокировать повторное действие до завершения записи.
- **FR-006**: Не менять ключи, JSON-формат, расчёт количества и UI.

## Success Criteria

- **SC-001**: Ошибка создания journal оставляет товары, заказы и форму без изменений.
- **SC-002**: Прерванное создание восстанавливает оба связанных ключа.
- **SC-003**: Ошибка удаления оставляет заказ и историю без изменений.
- **SC-004**: Прерванное удаление восстанавливает удалённый статус и историю вместе.
- **SC-005**: Полный Node suite и Simulator build проходят.
