# Research: черновики приёмки

На baseline `00ef151` первый вход в приёмку заказа записывал `receivingDraftV2` и `receivingIncomplete` прямо в живой объект, затем пытался сохранить весь `state.purchaseOrders`. Ошибка показывалась, но редактор открывался с несохранённым статусом. `saveReceivingDraft` повторял ту же мутацию и мог закрыть только при success, оставляя память уже изменённой при failure.

Для одного ключа critical journal не нужен. Решение использует полный clone массива, adapter write и публикацию после success. Уже сохранённый draft не требует записи при каждом открытии. Проведение прихода уже атомарно объединяет товары, заказ и историю и в этом срезе не меняется.
