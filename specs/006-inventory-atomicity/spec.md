# Feature Specification: атомарная инвентаризация

**Feature Branch**: `main`  
**Created**: 2026-10-01  
**Status**: Automated acceptance complete; manual acceptance deferred  
**Roadmap**: R1 Production acceptance 130.52  
**Finding**: A003-F03

## User Scenarios & Testing

### US1 — безопасная фиксация остатка (Priority: P0)

Фиксация строки меняет товар и черновик вместе. Ошибка storage сохраняет прежний остаток и
незафиксированную строку; частичная запись завершается journal при следующем запуске.

### US2 — безопасное завершение инвентаризации (Priority: P0)

Товары, история, дата периода и удаление черновика применяются одной операцией. UI показывает
завершение только после commit.

## Requirements

- **FR-001**: Не менять ключи и JSON-формат products/inventoryHistory/inventoryConfig/inventoryDraft.
- **FR-002**: Фиксация строки использует один journal для `products + inventoryDraft`.
- **FR-003**: Завершение использует один journal для четырёх связанных ключей.
- **FR-004**: `state` и вкладка меняются только после успешного commit.
- **FR-005**: Некорректный или отрицательный фактический остаток не сохраняется.
- **FR-006**: Повтор во время commit блокируется.
- **FR-007**: Не менять расчёт расхождений, стоимость, UI и версию.

## Success Criteria

- **SC-001**: Ошибка начала journal не меняет товар, черновик, историю или конфигурацию.
- **SC-002**: Частичная запись fix и complete полностью восстанавливается после `loadAll()`.
- **SC-003**: Успешное завершение создаёт одну запись истории и удаляет черновик.
- **SC-004**: Полный Node suite и Simulator build проходят.
