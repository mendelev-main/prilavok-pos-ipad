# Feature Specification: Loyalty and analytics presentation

**Roadmap**: R12

**Baseline**: M POS 130.54

**Date**: 2026-10-02

## Goal

Стандартизировать статическое оформление интерфейсов лояльности и аналитики без изменения расчётов, начислений, сетевых запросов и локальных чеков.

## User scenarios

1. Сотрудник просматривает выбранного клиента и доступные программы лояльности в текущем заказе.
2. Администратор просматривает карточку клиента, покупки и историю начислений.
3. Сотрудник открывает аналитику, выбирает период и видит прежние показатели и диаграммы.

## Requirements

1. `loyalty.js` не содержит inline style attributes.
2. В `analytics.js` inline styles остаются только для динамической ширины полос диаграмм.
3. Статическое оформление аналитических секций, скрытых значений и loyalty modal задаётся классами.
4. Loyalty API, начисления, списания подарков, analytics calculations и local orders не меняются.
5. Полная автоматизированная матрица и simulator build проходят.

## Success criteria

- В `loyalty.js` остаётся 0 inline style attributes.
- В `analytics.js` остаются ровно 2 проверяемых dynamic width templates.
- Loyalty и analytics экраны корректны в light/dark themes.
- Существующие тесты расчётов и лояльности проходят без регрессий.

## Out of scope

- Изменение правил программ лояльности.
- Изменение backend API.
- Новые аналитические метрики.
- Изменение доступа к финансовым показателям.
