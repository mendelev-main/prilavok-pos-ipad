# Research: поставщики

На baseline `a06ec3e` create/edit/delete поставщика сначала мутировали `state.suppliers`, затем вызывали `saveKey` и без ожидания закрывали окно с сообщением об успехе. При storage failure изменение исчезало после перезапуска.

Заказы и приёмки хранят `supplierId` и снимок `supplierName`; удаление справочной записи не требует и не должно каскадно менять историю. Для одного storage key достаточно прямого adapter write над отдельным снимком. Редактирование меняет только `name` и `productIds`, сохраняя неизвестные поля.
