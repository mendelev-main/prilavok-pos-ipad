# Feature Specification: ограничение ожидания программы лояльности

**Feature Branch**: `main`  
**Created**: 2026-10-01  
**Status**: Automated acceptance complete; manual acceptance deferred  
**Roadmap**: R1 Production acceptance 130.52  
**Finding**: A003-F06

## User Scenario

Если backend программы лояльности не отвечает, кассир получает существующий выбор продолжить
оплату без подарка не позднее чем через пять секунд. Локальный чек и корзина не меняются во время
проверки.

## Requirements

- **FR-001**: Ограничить каждый запрос `loyaltyApi()` пятью секундами.
- **FR-002**: Отменять зависший `fetch` через `AbortController` и всегда освобождать таймер.
- **FR-003**: Сохранять переданный вызывающим кодом abort signal.
- **FR-004**: При timeout использовать существующий безопасный сценарий продолжения без подарка.
- **FR-005**: Не менять расчёт лояльности, локальные данные, UI или сетевые триггеры.

## Success Criteria

- **SC-001**: Никогда не завершающийся запрос прерывается по deadline.
- **SC-002**: Оплата не запускается до решения кассира и предлагает продолжить без подарка.
- **SC-003**: Полный Node suite и Simulator build проходят.
