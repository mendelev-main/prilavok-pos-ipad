# Research: модуль WEB-заказов

## Решение 1: классический script сохраняет совместимый публичный контракт

**Decision**: Подключить `Web/js/features/web-orders.js` обычным `<script>` и сохранить имена
существующих функций и переменных.

**Rationale**: Разметка вызывает функции через inline `onclick`, а другие участки `pos.html` обращаются
к ним напрямую. Первый архитектурный срез должен менять расположение кода, а не контракт выполнения.

**Alternatives considered**: ES module и IIFE с namespace отложены: они потребовали бы одновременно
переписать inline-обработчики и зависимости, расширив риск первого этапа.

## Решение 2: запуск после загрузки feature-компонента

**Decision**: Переместить единственный вызов `loadAll()` в короткий inline-script после
`web-orders.js`.

**Rationale**: `loadAll()` вызывает `startWebOrderEvents()` и восстановление журнала принятия.
Компонент должен быть определён до запуска загрузки, при этом сам алгоритм старта не меняется.

**Alternatives considered**: `defer`, динамический import и событие DOMContentLoaded отклонены,
поскольку меняют момент запуска и создают ненужную асинхронную границу.

## Решение 3: использовать существующую Xcode-группу Web

**Decision**: Разместить файл внутри `PrilavokPOS/Web`.

**Rationale**: Папка целиком уже включена в Copy Bundle Resources. Новый файл попадёт в приложение
без ручной правки `project.pbxproj`, что уменьшает конфликтность и риск упаковки.

## Решение 4: тестировать подключаемый файл

**Decision**: Fixture `product-stock.test.cjs` читает и исполняет фактический
`Web/js/features/web-orders.js` после основного inline-кода.

**Rationale**: WEB-сценарии уже покрывают EventSource, local-first acceptance, retry, восстановление,
клиента и время готовности. Исполнение production-файла защищает от расхождения тестовой копии.

## Решение 5: не менять данные и сеть

**Decision**: Перенести код без изменения ключей `webEvents`, `webOrderAcceptances`, `parked`,
структуры записей и URL backend.

**Rationale**: Этот этап улучшает границы исходного кода. Любое изменение поведения требует
отдельной спецификации и миграционного анализа.
