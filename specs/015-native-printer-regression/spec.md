# Feature Specification: регрессия native bridge и печати

**Feature Branch**: `main`  
**Created**: 2026-10-02  
**Status**: Automated acceptance complete; device deferred  
**Roadmap**: R7  

## User Scenario

Изменения POS не должны незаметно ломать маршрутизацию LAN-печати: платёжный чек, кухонный чек и
отчёт закрытия смены получают правильный документ, назначенный принтер и число копий.

## Requirements

- **FR-001**: Автоматическая печать использует только включённые для неё принтеры.
- **FR-002**: Ручная повторная печать использует все активные чековые принтеры.
- **FR-003**: Кухонный принтер получает только назначенные категории и не печатает пустой документ.
- **FR-004**: `kitchenPrinted` предотвращает повторную автоматическую кухонную печать.
- **FR-005**: Payload сохраняет тип документа, IP, порт, конфигурацию, комментарии и число копий.
- **FR-006**: Swift bridge сохраняет валидацию адреса, deadline и document contracts.
- **FR-007**: Raster/LAN и физический обрезчик проверяются на iPad в финальной ручной приёмке.

## Success Criteria

- **SC-001**: Детерминированные JS-тесты подтверждают routing, copies и category filtering.
- **SC-002**: Тесты подтверждают ручную печать, shift-close и отсутствие аварии без native bridge.
- **SC-003**: Полный Node suite и Simulator build проходят.
