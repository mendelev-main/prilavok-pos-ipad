# Feature Specification: восстановление старого WEB-принятия

**Feature Branch**: `main`  
**Created**: 2026-10-02  
**Status**: Automated acceptance complete; device deferred  
**Roadmap**: R1 Production acceptance 130.52  
**Finding**: A003-F14

## User Scenario

Если ранее сохранённый WEB-заказ уже находится в Отложенных, но его старая запись не содержит
обязательного времени готовности, POS просит кассира выбрать время и завершает подтверждение без
создания второй копии заказа.

## Requirements

- **FR-001**: Не отправлять backend пустое или некорректное время готовности.
- **FR-002**: Показать запрос времени один раз за сессию для каждой старой записи.
- **FR-003**: Сохранить выбранное время в существующем `webOrderAcceptances` до сетевого запроса.
- **FR-004**: Не создавать второй parked-заказ и не повторять кухонную печать.
- **FR-005**: После сетевой ошибки оставить запись пригодной для штатного автоматического retry.
- **FR-006**: Не менять новый сценарий принятия WEB-заказа и формат существующих ключей.

## Success Criteria

- **SC-001**: Старый journal без времени не вызывает сеть до выбора кассира.
- **SC-002**: После выбора journal содержит время и подтверждается существующим ACK-механизмом.
- **SC-003**: В Отложенных остаётся ровно один заказ.
- **SC-004**: Полный Node suite, JavaScript syntax и Simulator build проходят.
